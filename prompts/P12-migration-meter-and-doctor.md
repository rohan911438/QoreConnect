# P12 — Migration Meter and Doctor

**Goal:** A public Migration Meter page with checkable numbers, and a Doctor that explains why any account's next transaction would fail.

**Depends on:** P06, P09.

**Read first:** `idea/02-solution.md` (Migration Meter), `architecture/03-flows.md` (Flows G and H), `architecture/04-relayer.md` (API).

**Time box:** 5 hours.

---

## Prompt

> 1. **Define the metrics precisely** in `docs/migration-meter.md` before coding. For each: definition, data source (REST endpoint, precompile, relayer DB), refresh interval, known limitations (testnet history is pruned; we keep our own series from the first day). Minimum set:
>    - Accounts onboarded through QoreConnect
>    - Classical keys under a post-quantum root (session + agent keys linked)
>    - Relayed executions (count, value) and refusals by the chain (count, by code)
>    - Sampled EVM-lane senders with vs. without a registered ML-DSA key (sample recent blocks via EVM RPC, check `pqcKeyStatus`)
>    - dApps integrated (distinct gas tanks with at least one relay)
>    - Countdown to Q3 2027 (EVM lane "Required" target, labelled as QoreChain's roadmap target)
> 2. **Indexer** in `packages/relayer`: a periodic job writing `meter_snapshots`; endpoints `GET /v1/meter` and `GET /v1/meter/series`. Every number includes a `source` link.
> 3. **Page `/meter`** in `apps/web`: headline numbers, a time-series chart, the countdown, "How we count" section linking `docs/migration-meter.md`, and a source link next to every number. Shareable Open Graph image.
> 4. **Doctor:** `GET /v1/doctor/:address?target=0x…` running the checks in Flow G in order; page `/doctor` with an address input and one-click fixes that open the right flow (onboard, approve, renew).
> 5. Tests: metric computation from fixtures; Doctor check ordering and outputs for each failure case.

---

## Deliverables

- `docs/migration-meter.md`
- Indexer, API, `/meter` and `/doctor` pages
- Tests

## Validation gate

| # | Check | Pass condition |
|---|---|---|
| G1 | Tests | Pass |
| G2 | Checkability | For 3 numbers chosen at random, following the source link reproduces the number (manual) |
| G3 | Doctor | Correct first failure for: fresh address (no key), linked but expired, contract not approved, healthy |
| G4 | Page quality | Loads in under 2 s; readable on mobile; OG image renders |

## Failure branch

- EVM sender sampling too slow or rate-limited: reduce sample size and label it as a sample with its size.
- Time short: ship a static snapshot page generated by a script, labelled with its timestamp (cut order item 3).
