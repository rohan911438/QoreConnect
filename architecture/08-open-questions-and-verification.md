# 08 — Open questions and verification plan

The design depends on assumptions the docs do not fully confirm. Prompt **P01** tests each one on Diana testnet before any product code is written. This table is the single source of truth for their status; P01 updates it.

| # | Question | Why it matters | How P01 tests it | If the answer is bad | Status |
|---|---|---|---|---|---|
| Q1 | Can a MetaMask-linked authenticator execute a **contract call with calldata** via `MsgExecuteEVM` (not only a value transfer)? | Without it, dApps cannot be used at all | Deploy a Counter; link a test secp256k1 key as an `eth` authenticator; build `MsgExecuteEVM` with `data = increment()`; relay; check the counter | **Blocker.** Inspect the SDK source for a lower-level builder; if impossible, pivot (see P01 failure branch) | Unverified |

## Facts already established (from docs, 21 Nov 2026)

- Testnet: chain id `qorechain-diana`, EVM chain id 9800, chain version v3.2.8 since 12 Nov 2026.
- Abstract accounts enabled on testnet (proposal 18, 27 Oct 2026), disabled on mainnet (code 9).
- Possession proof required since v3.2.8; SDK 0.14.0 and wallet-adapter 0.6.0 support it.
- Precompiles: `pqcVerify` `0x0000000000000000000000000000000000000a01`, `pqcKeyStatus` `0x0000000000000000000000000000000000000a02` (testnet only).
- Fee floor 0.1 uqor per gas; docs example 400,000 gas with 40,000 uqor.
- ML-DSA key registration about 600k gas; pubkey 2,592 bytes, signature 4,627 bytes.
- QoreX refuses EVM signing methods and emits no `accountsChanged` / `chainChanged`.
- Faucet: once per 24 h per account; also gives fUSD, fETH, fBTC.
- Endpoints: RPC `https://rpc-testnet.qore.host`, REST `https://api-testnet.qore.host`, EVM RPC `https://evm-testnet.qore.host`, explorer `https://explore.qore.network`.
